## 結論：記録は書かない。自動で残す

残業時間の記録は、メモを書くことではありません。Claude Codeのセッションが始まった時刻と終わった時刻を、フックで自動的にファイルへ残します。月末に、その記録と申告した時間を並べる。実績のほうが長い日が、申告漏れの候補です。

連合総研の調査（2026年11月19日発表）では、残業手当の支給対象で9月に所定外労働をした人の26.9%に、申告していない時間がありました。平均11.1時間。未申告があった人の72.9%は「自分で調整した」と答えています。数えていない時間は、給与にも記録にも残らない。まず数える。そこからしか始まりません。

出典： 連合総研「時間外労働の実態と意識に関する調査」（2026年11月19日発表）
https://www.rengo-soken.or.jp/info/2025/11/6602/

## 「見えない残業」とは何か

申告していない時間外労働のことです。サービス残業、と言い換えてもいい。

調査では、未申告の理由として「時間外労働の上限規制に抵触するため」が15.0%、「上司から指示されたため」が12.5%ありました。自分の意思で調整した、という人ばかりではありません。

この記事でやるのは、請求の話ではありません。自分の時間を、まず事実として数えることだけです。

## 仕組みは3つだけ

1. Claude Codeのフックで、セッションの開始と終了を自動で記録する
2. 終業時刻を過ぎたセッションの時間を、その日の作業時間として数える
3. 月末に、記録と申告した時間を並べて、差がある日を出す

メモを書く手間はありません。仕事を始めたらセッションが始まり、終われば終わる。その時刻が残ります。

## 設定は一度だけ

Claude Codeには、セッションの開始時と終了時に決まった処理を自動で動かす「フック」という仕組みがあります。プロジェクトの設定ファイル `.claude/settings.json` に、次の形で書きます（抜粋）。

```json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [
        { "type": "command",
          "command": "python3 \"$CLAUDE_PROJECT_DIR/hooks/log_session.py\" start" }
      ] }
    ],
    "SessionEnd": [
      { "hooks": [
        { "type": "command",
          "command": "python3 \"$CLAUDE_PROJECT_DIR/hooks/log_session.py\" end" }
      ] }
    ]
  }
}
```

`log_session.py` の中身は、渡されたセッションIDと現在時刻をCSVに1行足すだけです。このスクリプト自体も、Claude Codeに頼んで作ってもらえます。「セッションの開始と終了で呼ばれたら、日時とセッションIDを session-log.csv に追記するスクリプトを書いて」と頼むところから始めてください。

記録はこういう形でたまっていきます。

```
datetime,event,session_id
2026-11-24T21:03:12+09:00,start,8f3a…
2026-11-24T22:47:05+09:00,end,8f3a…
```

開始と終了が同じセッションIDで対になるので、差を取ればその回の作業時間です。

## 記録の置き場所と、書かれるもの

記録ファイル（session-log.csv）は、自分の端末の中だけに置きます。社外のサービスには上げません。

記録されるのは、日時とセッションIDだけです。作業の中身は記録されません。逆に言えば、セッションを開いていた時間しか数えられません。電話対応や、紙の資料を読む時間は、この仕組みの対象外です。そこは割り切ってください。

## 月末に、申告と並べる

月末に、Claude Codeへこう頼みます。

> 今月分について、終業時刻を過ぎたセッションの時間を、日ごとに合計して。申告した時間と並べて、差がある日を出して。

申告した時間の一覧は、自分の勤怠の控えから渡します。結果はこんな形で返ってきます。

```
2026-11-24 | 実績 1:44 | 申告 1:00 | 差 0:44 ← 候補
2026-11-25 | 実績 0:47 | 申告 0:47 | 差 0:00
```

差がある日が、申告漏れの候補です。あくまで候補。セッションを開きっぱなしにしていた、といった理由もあるはずです。候補を見て、自分の記憶と照らして確かめる。そこまでは機械に任せて、判断は自分でします。

CLAUDE.mdに「記録は端末内だけに置く」「個人を特定できる情報は記録しない」と書いておくと、毎回同じ注意を繰り返さずに済みます。

## 数えた先は、自分で決める

差分をどう扱うかは、この記事では決めません。申告し直すのか、上司に相談するのか、まず記録だけ続けるのか。個別の請求の助言にも踏み込みません。

ただ、数えていない時間は、交渉の材料にもなりません。自分の時間を自分で把握していること。それが先です。

次回は、AIに任せる範囲を決める「権限設定」の話をします。便利さと安全の境目は、設定で引けます。

## よくある質問

**Q. 残業時間の記録は、どうやって始めればいいですか**
A. Claude Codeのフック設定を一度だけ入れてください。セッションの開始と終了が自動で記録されるので、あとは月末に申告と並べるだけです。最初の依頼の立て方は第1夜「Claude Codeはじめの一歩：インストールから最初の依頼まで」もあわせてどうぞ。

**Q. 記録した残業時間は、どう使えばいいですか**
A. 自分の手元に残すのが先です。月末に申告した時間と並べて、差分を「申告漏れの候補」として確認するのがこの仕組みの役割です。差分をどう扱うか（申告し直すか、相談するか）は、この記事では決めません。個別の請求の助言には踏み込みません。

**Q. 会社でClaude Codeを使っても大丈夫ですか（情報漏洩が心配です）**
