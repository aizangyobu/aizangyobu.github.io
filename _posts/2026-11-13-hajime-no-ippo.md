## 結論：最初の依頼は「読むだけ」の仕事から始める

Claude Codeの第一歩は、インストールしても、いきなりコードを書かせないことです。最初の依頼は「このフォルダの中身を要約して」のような、読み取りだけの仕事から。安全ですし、動きの感覚もつかめます。

この記事には、練習に使うフォルダ一式をそのまま載せました。サンプルファイルとプロンプト集まで全部入りです。インストールが終わったら、この一式をコピーして、最初の依頼まで一気に進められます。

## Claude Codeとは何か

Claude Codeは、Anthropicが提供するコーディングエージェントです。ターミナル（コマンドを入力する黒い画面）の中で動き、ファイルの読み書き、コマンドの実行、調査や文書作成までを、自然言語の依頼で代行します。チャットで答えをもらうのではなく、「作業そのものを任せる」道具だと考えると分かりやすいです。

## 手順1：インストールする

前提として、公式の案内に従い以下のいずれかでインストールします。

- ネイティブインストーラ（macOS / Linux）: 公式サイトの案内に沿ってコマンドを1行実行
- Windows: 公式の案内に従ってインストール（WSL環境が必要な場合があります）
- npmを使う方法もあります。Node.js 18以上を入れたうえで `npm install -g @anthropic-ai/claude-code`

インストールできたら、ターミナルで `claude --version` と入力し、バージョンが表示されるか確認します。表示されれば第一関門は通過です。

つまずきポイント: npmで入れた場合に権限エラー（EACCES）が出ることがあります。その場合は公式ドキュメントのトラブルシューティングに沿って、npmのグローバルインストール先を変更するのが定石です。安易に管理者権限で実行し直すのは避けましょう。

## 手順2：サインインする

作業フォルダに移動して `claude` と入力すると、初回はサインインが求められます。ブラウザが開きます。Anthropicのアカウントでログインして、ターミナル側に戻れば完了です。利用にはClaudeの有料プラン、またはAPI利用の契約が必要です（最新の料金条件は公式サイトで確認してください）。

## 実物：練習用フォルダ一式

サインインの前に、練習の舞台を用意します。大事なフォルダでいきなり始めない、がこの部の初期ルールです。練習用フォルダは、中身が全部サンプルなので、何を壊しても実害がありません。

構成はこうです。

```
claude-practice/
├── README.md            … このフォルダの説明（練習用であること）
├── notes/
│   ├── meeting-memo.md  … サンプルの会議メモ
│   └── ideas.md         … サンプルのアイデアメモ
└── data/
    └── tasks.csv        … サンプルのタスク一覧
```

各ファイルの中身も全文を置いておきます。この通りに作れば、以降の手順がそのまま再現できます。

**README.md**

```markdown
# 練習用フォルダ

Claude Codeの練習専用フォルダです。中身はすべてサンプルデータで、
実在の業務情報・個人情報は含まれていません。

- notes/ … メモ類のサンプル
- data/  … 表データのサンプル

成果物を試しに作らせる場合は、このフォルダの中に作らせてください。
```

**notes/meeting-memo.md**

```markdown
# 定例会議メモ（サンプル）

- 日付: 2026-11-10
- 出席: 営業チーム、制作チーム

## 決まったこと
- 来月のキャンペーンは第2週から開始する
- 資料の締め切りは前週の金曜日に前倒しする

## 宿題
- 営業チーム: 見積のたたき台を作る
- 制作チーム: バナーのサイズ一覧を共有する

## 次回
- 2026-11-17、同じ時間
```

**notes/ideas.md**

```markdown
# アイデアメモ（サンプル）

- 月次レポートの集計を、毎回手でやるのをやめたい
- 会議メモから宿題だけを抜き出す仕組みがほしい
- ファイル名の付け方をチームで統一したい
```

**data/tasks.csv**

```csv
タスク,担当,期限,状態
見積のたたき台作成,営業チーム,2026-11-14,未着手
バナーサイズ一覧の共有,制作チーム,2026-11-13,進行中
月次レポート集計,制作チーム,2026-11-28,未着手
会議室の予約更新,営業チーム,2026-11-20,完了
```

サンプルは「会議メモ」「アイデアメモ」「タスク表」の3種類にしました。会社員の手元に似た形のファイルがある組み合わせで、要約・抜き出し・集計の練習が一通りできます。自分の業務ファイルで試すのは、この一式で感覚をつかんでからにしてください。

## 手順3：最初の依頼は「読むだけ」から

`claude-practice` フォルダに移動して `claude` を起動し、まず読み取りだけの依頼をしてみます。プロンプト集の1本目です。

```
このフォルダにあるファイルの一覧と、それぞれの役割を教えてください。変更はしないでください。
```

ポイントは最後の一文です。「変更はしないでください」と明示すると、最初の体験が事故なく終わります。Claude Codeはファイル変更やコマンド実行の前に許可を求める設計ですが、最初は依頼側でも「読むだけ」と線を引くのが安全です。

## 手順4：2回目の依頼で「小さく書かせる」

感覚がつかめたら、小さな作成を任せます。プロンプト集の2本目（要約）と3本目（新規作成）です。

```
notes/meeting-memo.md を読んで、決まったことと宿題を、それぞれ3行以内に要約してください。ファイルへの変更はしないでください。
```

```
data/tasks.csv を読んで、状態が「未着手」のタスクだけを抜き出し、期限の早い順に並べた todo.md を新規作成してください。既存ファイルは変更しないでください。
```

新規ファイルの作成なら、失敗しても消せば済みます。「既存ファイルの書き換え」は、動きに慣れてからにしましょう。

## 許可ダイアログの判断表

作業中、Claude Codeは操作の前に許可を求めてきます。最初は「何を許可していいのか」が一番の不安です。判断の目安を表にしました。

| 求められる操作 | 最初はどうするか | 理由 |
|---|---|---|
| ファイルを読む | 許可してよい | 変更は起きない。読み取りは練習の基本 |
| 新規ファイルを作る | 中身のプレビューを見てから許可 | 消せば戻せる。ただし作る場所と名前は確認する |
| 既存ファイルを書き換える | 差分（変更前後）を見てから判断 | 慣れるまでは、書き換え内容を全部読める大きさの変更だけ許可する |
| コマンドを実行する | コマンドの意味が分からなければ止める | 削除や移動のコマンドは特に慎重に。分からないものは許可しないのが正解 |
| ファイルを削除する | 最初は許可しない | 練習用フォルダ以外では取り返しがつかない。削除は慣れてからの操作 |
| 外部へ送信・公開する操作 | 許可しない | 送信先と内容を人が確認するまでは、自動で出さない |

迷ったら「止める」が正解です。止めても作業が壊れることはありません。再開はいつでもできます。

## 安全に始めるための3つの初期ルール

1. **大事なフォルダでいきなり始めない** — 最初は練習用のフォルダで始めます。削除や上書きの影響がない場所で感覚をつかむこと
2. **秘密情報を置いたまま作業しない**: パスワードやAPIキーが書かれたファイルがあるフォルダでは、作業範囲を意識します（詳しくは第7夜「秘密情報を渡さないための設定」で扱います）
3. **変更前の確認を省略しない** — 許可を求められたら、内容を読んでから承認します。「全部許可」は慣れてからでも遅くありません

## 次回予告

第2夜は「CLAUDE.mdに何を書くか」です。プロジェクトの前提や約束事をファイルに書いておくと、毎回の説明が不要になります。そのまま使える雛形付きで公開します。練習用フォルダにCLAUDE.mdを足すところから始めると、手順がつながります。
